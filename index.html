Системи контролю версій: Git

Практичний довідник та звіт з опрацювання теми

1. Системи контролю версій (VCS) та Git

Система контролю версій (Version Control System, VCS) — це програмне забезпечення, що фіксує зміни у файлах з плином часу, дозволяючи повертатися до попередніх версій, відстежувати історію модифікацій, порівнювати правки та організовувати спільну роботу команди над кодом.

Git — це розподілена система контролю версій (Distributed VCS), створена Лінусом Торвальдсом у 2005 році. На відміну від централізованих систем (таких як SVN чи CVS), у Git кожен розробник має повну локальну копію всього репозиторію разом із повною історією коммітів, що забезпечує високу швидкість роботи та можливість працювати офлайн.

2. Основні можливості та переваги використання Git

  • Розподілена архітектура: відсутність єдиної точки відмови (Single Point of Failure); локальні операції виконуються миттєво.
  • Швидка та легковагова робота з гілками (Branching & Merging): створення, перемикання та злиття гілок реалізовані максимально оптимізовано, що заохочує використання feature-гілок.
  • Цілісність даних: кожен об'єкт і стан проекту підписуються криптографічним хешем (SHA-1 / SHA-256), що гарантує захист від непомітного пошкодження або зміни історії.
  • Індексування (Staging Area): проміжний стан перед фіксацією дозволяє вибірково формувати комміт лише з потрібних змін.
  • Масштабованість та інтеграція: Git став фактичним стандартом індустрії й підтримується провідними сервісами (GitHub, GitLab, Bitbucket) та сучасними IDE.

3. Топ-10 базових команд Git з коментарями

Команда Призначення та коментар
git init Ініціалізує новий локальний Git-репозиторій у поточній директорії (створює приховану папку .git).
git clone <url> Клонує (копіює) існуючий віддалений репозиторій на локальний комп'ютер разом з усією історією.
git status Відображає поточний стан робочого каталогу: змінені, підготовлені (staged) або невідстежувані файли.
git add <file> Додає зміни файлу до області індексування (Staging Area) для підготовки до комміту (git add . — додати всі).
git commit -m "msg" Зберігає проіндексовані зміни в історії проекту зі зрозумілим повідомленням про внесені правки.
git branch Переглядає список локальних гілок. З прапорцем -M <name> перейменовує гілку, з <name> — створює нову.
git checkout <branch> Перемикає робочий стан на вказану гілку (у новіших версіях Git також використовується git switch).
git merge <branch> Об'єднує зміни з зазначеної гілки в поточну активну гілку.
git pull Завантажує та одразу інтегрує (об'єднує) зміни з віддаленого репозиторію в поточну локальну гілку.
git push origin <branch> Надсилає зафіксовані локальні комміти у віддалений репозиторій на сервері.
