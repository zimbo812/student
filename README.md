# Основи роботи з системою контролю версій Git

## 1. Що таке система контролю версій (VCS) та Git?
**Система контролю версій (VCS)** — це програмне забезпечення, яке фіксує історію змін у файлах проекту. Вона дозволяє повертатися до будь-якої точки в минулому, аналізувати зміни та працювати над кодом у команді без ризику перезаписати чужу роботу.

**Git** — це розподілена система контролю версій (Distributed VCS). Це означає, що кожен розробник зберігає повну локальну копію всієї історії репозиторію. Створена Лінусом Торвальдсом у 2005 році як надійний та швидкий інструмент для розробки ядра Linux.

---

## 2. Основні можливості та переваги Git
* **Розподілена структура:** Більшість операцій виконуються локально й миттєво (без потреби в інтернет-з'єднанні).
* **Гілкування та злиття (Branching & Merging):** Легке та швидке створення ізольованих гілок для кожної нової фічі чи виправлення помилок.
* **Цілісність даних:** Кожна зміна та стан проекту контролюються криптографічним хешуванням (SHA), тому непомітно змінити історію неможливо.
* **Трьохетапна архітектура:** Чіткий розподіл на робочу директорію (*Working Directory*), область індексування (*Staging Area*) та власне сховище коммітів (*Repository*).

## 3. Топ-10 базових команд Git

| № | Команда | Призначення та коментар |
|---|---------|-------------------------|
| 1 | `git init` | Створює новий локальний репозиторій у поточній папці (папка `.git`). |
| 2 | `git clone <url>` | Завантажує існуючий віддалений репозиторій із мережі на локальний ПК. |
| 3 | `git status` | Показує поточний стан файлів (змінені, готові до коміту, невідстежувані). |
| 4 | `git add <file>` | Додає змінений файл до індексу (staging area). Для додавання всіх змін: `git add .` |
| 5 | `git commit -m "msg"` | Фіксує підготовлені зміни в історії проекту з текстовим описом. |
| 6 | `git branch` | Виводить список гілок. Прапорець `-b <назва>` у поєднанні з checkout створює нову гілку. |
| 7 | `git switch <branch>` | Перемикає робочий стан на вказану гілку (аналог класичної `git checkout`). |
| 8 | `git merge <branch>` | Об'єднує вказану гілку в активну поточну гілку. |
| 9 | `git pull` | Завантажує та інтегрує свіжі комміти з віддаленого репозиторію в локальний. |
| 10| `git push origin <branch>` | Відправляє зафіксовані локальні комміти у віддалений репозиторій (наприклад, на GitHub). |
